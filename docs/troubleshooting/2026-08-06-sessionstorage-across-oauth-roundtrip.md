# OAuth 왕복을 건너 사실을 전달한다 — sessionStorage 패턴과 그 함정

- 날짜: 2026-08-06
- 관련 이슈키: S15P11A705-347

## 증상

탈퇴가 완료돼도 사용자는 아무 확인 문구를 보지 못했다. 공급자 화면을 거쳐 돌아오면 쿠키가 만료된 채 `/auth/callback`에 착지하고, 앱 시작 흐름이 그대로 로그인 화면으로 보낸다. **되돌릴 수 없는 동작인데 완료 신호가 없다.**

일반화하면 이렇다. **공급자 도메인을 다녀오는 전체 페이지 이동은 자바스크립트 메모리를 전부 버린다.** React state·Context·모듈 변수 어디에 담아도 왕복 뒤에는 남아 있지 않다. 그래서 "이동 전에 알고 있던 사실"을 착지 후에 쓸 수 없다.

여기에 계약 조건이 겹친다. `08_API_명세.md` §3.6.2에서 **탈퇴 성공은 `error` 없이 로그인과 같은 콜백으로 착지한다.** 성공을 알리는 쿼리 파라미터가 없다. 따라서 콜백만 봐서는 "탈퇴를 마치고 돌아온 것"과 "평범한 로그인"이 구분되지 않는다.

## 원인

원인이라기보다 구조적 제약이다. 그리고 **서버 계약을 바꿀 필요는 없다** — 탈퇴를 시작한 것은 프론트 자신이라 그 사실을 스스로 기억하면 된다. 성공에 파라미터를 두지 않는 §3.6.2의 근거는 그대로 유효하다.

## 해결

**`sessionStorage`를 쓴다. 탭 단위로 살아 있어 다른 도메인을 다녀오는 전체 페이지 이동을 건너 유지된다.**

이 레포에는 이미 같은 문제를 같은 방법으로 푼 선례가 있다 — `preLoginPath.ts`가 로그인 시작 전 경로를 보관해 콜백 성공 시 복귀에 쓴다. `withdrawalNotice.ts`를 같은 형태(save/get/clear)로 만들었다.

```
탈퇴 「예」  → sessionStorage에 표시 저장 → window.location.href = authorizationUrl
콜백 착지   → error 없음 + 표시 있음  → "탈퇴가 완료되었습니다"
            → error 없음 + 표시 없음  → 평범한 로그인
            → error 있음              → 기존 WITHDRAWAL_* 분기
읽은 뒤 즉시 표시를 지운다
```

**저장은 반드시 이동보다 먼저다.** `window.location.href` 이후에는 이 문서가 버려지므로 그 뒤에 쓴 코드는 실행을 보장할 수 없다.

## 재발 방지

이 패턴에는 함정이 셋 있다. 셋 다 "표시가 살아남아 거짓을 말하는" 형태다.

**1. 읽으면 즉시 지운다.** 남겨두면 같은 탭의 다음 로그인에서 또 뜬다. 한 번 알리고 끝나야 한다.

**2. 실패 분기에서도 지운다.** 이것이 놓치기 쉽다. `WITHDRAWAL_CANCELLED`(사용자가 공급자 화면에서 취소)로 돌아왔을 때 표시를 안 지우면, 나중에 같은 탭에서 평범히 로그인할 때 **계정이 멀쩡히 살아 있는데도 "탈퇴가 완료되었습니다"가 뜬다.** 이번에는 `WITHDRAWAL_*`뿐 아니라 `OAUTH_FAILED`에도 적용했다 — 어느 쪽이든 왕복이 그 착지로 끝났고 회원은 지워지지 않았으니, 표시가 살아남을 이유가 같다.

**3. 지우기만으로는 막지 못하는 경로가 남는다.** 사용자가 공급자 화면에서 그냥 이탈하면 **콜백이 아예 오지 않아 지울 기회가 없다.** 그 상태로 나중에 같은 탭에서 로그인하면 `error` 없이 착지해 완료 문구가 뜬다. 그래서 저장 시각을 함께 넣고 경과 시간으로 끊는다.

TTL 값에 대해서는 판단이 하나 필요했다. 이슈는 "인가 요청 쿠키 수명(10분)"을 기준으로 검토하라고 했으나, `08_API_명세.md` §3.6과 `11_인증_설계.md`를 확인한 결과 **그 수명은 참조 문서에 공개돼 있지 않다**(문서화된 것은 Access 30분 / Refresh 7일뿐이다). 그래서 10분을 서버 값의 반영인 것처럼 쓰지 않고 **프론트가 정한 안전장치**로 명시해 주석에 적었다. 서버 정책을 추측해 옮기지 않는다(AGENTS.md).

**기울기는 항상 "무시하는 쪽"으로 잡는다.** 경계를 넘겨 표시를 무시하면 최악의 결과가 "완료 문구를 못 본다"이지만, 낡은 표시를 믿으면 "탈퇴하지도 않았는데 탈퇴됐다고 알린다"가 된다. 같은 이유로 미래 시각(기기 시계가 되돌아간 경우)과 숫자가 아닌 값(다른 코드·확장이 덮어쓴 경우)도 무시한다.

**되돌릴 수 없는 동작의 완료 문구는 취소 문구와 분명히 달라야 한다.** 사용자가 둘을 헷갈리면 실제로 어느 쪽인지 확인할 방법이 없다. 여기서는 `탈퇴가 완료되었습니다. 그동안 이용해 주셔서 감사합니다.`와 `탈퇴를 취소했습니다.`로 나눴다.

**표시 수단**: 이 레포엔 토스트·스낵바가 없어 `window.alert()`를 썼다(`handleOAuthCallback`의 기존 실패 알림과 같다). 그 자리의 `⚠️ alert() placeholder다` 주석은 여전히 유효하다 — 알림 컴포넌트를 도입하면 이 문구도 함께 옮긴다.
