아래 작업을 계획한다. 코드를 작성하지 말고 계획만 제시한다.

작업: $ARGUMENTS

## 진행

1. 먼저 관련 문서를 확인한다: `docs/api-contract.md`, `docs/privacy-rules.md`, `docs/architecture.md`, `docs/conventions.md`, 필요 시 `docs/reference/`.
2. 작업을 **하위 단계**로 분해한다(각 단계는 검증 가능한 단위로).
3. 각 단계에서 지켜야 할 계약·공개 범위 규칙을 근거 문서와 함께 짚는다.
4. `api-contract.md`의 [협의 필요]에 걸리는 부분이 있으면 **먼저 확인이 필요하다고 표시**한다(임의 결정 금지).

## 출력 형식

### 하위 단계

1. …
2. …

### Jira 이슈 제목 후보

- (2~3개, 간결한 한국어. 이슈키는 나중에 발급되므로 번호는 비워둔다)

### 브랜치 이름

- `feature/S15P11A705-<번호>-<설명>` 형식 제안 (설명은 영소문자-하이픈)
- 커밋 예: `feat(S15P11A705-<번호>): 설명`
- PR 제목 예: `[S15P11A705-<번호>] 설명`

### 관련 참조 문서

- (읽어야 할 `docs/` 및 `docs/reference/` 문서와 해당 절)

### 확인 필요 (있으면)
